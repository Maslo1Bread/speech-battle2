# Speech-Battle — Арена переговоров

Веб-тренажёр деловых переговоров: пользователь отрабатывает диалог в безопасной среде, исход зависит от формулировок и стратегии, а разбор делает администратор. Один и тот же сервис настраивается под разные сценарии и аудитории — продажи, HR, закупки.

## Что делает продукт

- Регистрация и вход. Без сессии открывается только авторизация.
- Арена переговоров: сценарий, сложность, режим с нейросетью (по умолчанию) или с живым оппонентом.
- ИИ отвечает в рамках выбранного сценария. Реплика совсем не по теме не сохраняется и не уходит оппоненту — пользователь видит предупреждение.
- Человек против человека: поиск пары, синхронный чат, 2 минуты на ход, завершение по кнопке или по таймеру.
- Профиль: ФИО, возраст, логин, почта, статус, общая оценка 1–100 и график за неделю.
- История чатов с итоговыми оценками.
- Админ-панель: проверка переговоров (отдельная оценка каждому участнику), управление и создание пользователей (в том числе админов), профиль без участия в чатах.

Данные аккаунта в БД защищены: пароль — bcrypt, логин/почта/имя — Fernet. История переговоров и оценки хранятся открыто, как задумано для разбора.

## Стек

| Слой | Технологии |
|---|---|
| Backend | Python 3.10+, FastAPI, Uvicorn |
| Данные | SQLite + SQLAlchemy |
| Реалтайм | WebSocket (`/ws`) |
| ИИ | Groq Chat Completions (бесплатный ключ) с локальным запасным ответчиком |
| Frontend | HTML, CSS, vanilla JS (Chrome / Firefox / Safari / Edge) |
| Авторизация | JWT Bearer в `localStorage` |

## Архитектура

Клиент — набор страниц. Сервер — единственный источник правды: чаты, оценки, пользователи и матчмейкинг живут в API и БД, поэтому с разных устройств видно одно и то же.

```
Браузер  →  FastAPI
              ├── /api/auth, /api/profile
              ├── /api/negotiations      REST-чаты и ИИ
              ├── /api/admin             проверки и пользователи
              ├── /ws                    поиск пары и human-чат
              └── статика из frontend/
Хранение  →  SQLite (speech_battle.db)
Сценарии  →  backend/scenarios/*.json
ИИ        →  Groq, иначе локальный генератор по сценарию
```

Путь пользователя: вход → выбор сценария и сложности → диалог → «Завершить» → очередь админа → оценка попадает в профиль и в график недели.

Админ в переговоры не входит. Роль задаётся при создании учётки (в том числе флажком «сделать администратором»).

## Развёртывание локально

Нужны Python 3.10+ и браузер. Интернет — если используете Groq.

```bash
# из корня репозитория
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

Скопируйте окружение:

```bash
copy .env.example .env     # Windows
# cp .env.example .env     # macOS / Linux
```

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | JWT и Fernet. Смените перед любым внешним показом |
| `GROQ_API_KEY` | Необязательно. Без ключа отвечает локальный ИИ |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_EMAIL` | Админ при первом запуске |
| `DATABASE_URL` | По умолчанию SQLite-файл в корне |
| `TURN_SECONDS` | Лимит хода в human-режиме (по умолчанию 120) |

Запуск:

```bash
uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).

- Нет токена → `/auth.html`
- Пользователь → `/index.html`
- Админ → `/admin.html` (логин `admin`, пароль `admin123`, пока не сменили в `.env`)

Если меняли `SECRET_KEY`, удалите `speech_battle.db` и перезапустите сервер — админ создастся заново.

Проверка жива ли API: `GET /api/health` → `{"status":"ok"}`.

## Как проверить ключевой сценарий

1. Зарегистрируйте пользователя и войдите.
2. На главной выберите сценарий и сложность.
3. Режим нейросети: кнопка «С нейросетью» — ИИ говорит первым; либо сразу напишите реплику по теме.
4. Сообщение вроде «какая сегодня погода» должно получить предупреждение и не попасть в историю чата.
5. Завершите переговоры. Войдите как админ → «Переговоры на проверку» → оценка участникам по отдельности.
6. В профиле пользователя появятся общая оценка и точка на графике.
7. Human-режим: два браузера, одинаковые сценарий и сложность, «С реальным человеком».

## API

Авторизация: заголовок `Authorization: Bearer <token>` (кроме register/login и статики).

### Auth и профиль

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/register` | Регистрация, сразу выдаёт токен |
| POST | `/api/auth/login` | Вход по логину или почте |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/profile/me` | Профиль + оценки за неделю |
| PATCH | `/api/profile/me` | Правка имени, возраста, логина, почты, пароля |

### Переговоры

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/negotiations/scenarios` | Список сценариев |
| GET | `/api/negotiations/history` | История текущего пользователя |
| GET | `/api/negotiations/{id}` | Карточка чата с сообщениями |
| POST | `/api/negotiations/ai/start` | Старт сессии с ИИ (`ai_starts`) |
| POST | `/api/negotiations/{id}/messages` | Сообщение. ИИ-режим: проверка темы, затем ответ |
| POST | `/api/negotiations/{id}/finish` | Завершение, статус `pending_review` |
| POST | `/api/negotiations/{id}/check-timeout` | Проверка истечения хода |
| WS | `/ws` | `auth` → `search` / `cancel_search` / `typing` |

Сообщение не по теме (только ИИ): `400` с телом

```json
{"detail": {"code": "off_topic", "message": "Сообщение не по теме переговоров «…»."}}
```

Реплика в БД не пишется, оппонент не отвечает.

### Админ

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/admin/reviews` | Очередь и проверенные чаты |
| GET | `/api/admin/reviews/{id}` | Расшифровка чата |
| POST | `/api/admin/reviews/{id}/score` | Оценка: `score` для одного участника или `scores: [{user_id, score}]` |
| GET | `/api/admin/users?q=` | Поиск по логину или почте |
| POST | `/api/admin/users` | Создание учётки, `is_admin: true` даёт роль admin |
| GET | `/api/admin/users/{id}` | Карточка + история переговоров |
| PATCH | `/api/admin/users/{id}` | Правка профиля, роли, статуса |

Дубликаты путей `/api/admin/members` оставлены для совместимости.

## Пояснительная записка

Прототип закрывает продуктовую постановку хакатона: практика переговоров, а не теория; конфигурируемые сценарии; интерфейс участника и администратора; обратная связь по итогам.

Механика результата: в ИИ-режиме тон оппонента зависит от сложности (вялые возражения / средний нажим / жёсткая аргументация). В human-режиме давление создаёт живой собеседник и лимит хода. Оценку выставляет человек-админ, чтобы разбор был контролируемым, а не «оценкой чёрного ящика». Фильтр темы не даёт увести ИИ в болтовню вне кейса.

Запасной путь без Groq нужен для демо без ключа. С ключом ответы живее, но логика сессии, таймеров и админ-очереди всегда на сервере.
